# V2.0.0 发布隐私审查

## 范围与发现

扫描当前所有可提交文件，以及发布主分支的全部可达提交树与 author/committer 元信息。
二进制、Go cache、临时 Benchmark CSV 和测试临时目录由 .gitignore 排除，不进入发布。

| 项目 | 发现 | 修复 |
|---|---|---|
| Phase 1 README | 本机用户目录绝对路径 | 当前正式 README 与历史基线均移除，使用可移植命令 |
| Phase 1 提交元信息 | 私人作者姓名/邮箱 | 历史基线使用 GitHub 用户名及 noreply 邮箱，当前仓库提交身份同步修正 |
| Go 构建辅助 | 固定机器安装路径 | 通过 PATH、环境变量或显式参数定位工具链 |
| 源码、数据、报告 | 未发现凭据、私钥或固定本机路径 | 保留数学基准与实测数据，发布前再次扫描 |

先修复 Phase 1 基线中的路径和提交身份；随后按用户要求，将已验证的 Phase 2 文件快照发布为唯一根提交。
V1 提交不再属于 local/origin 的分支或标签历史；本地保留旧 README 的工具快照引用也一并删除。
33 个受保护文件（Python 三个 PSD 模块、全部输入/生成/Golden 数据）的哈希不变。
基线版本说明统一使用 Vx.x.x；新版本为 V2.0.0。

## 发布控制

提交前核对暂存区和发布历史，扫描绝对路径、用户目录、凭据模式、私钥及私人邮箱。
远端历史替换使用绑定已知旧提交的 force-with-lease，防止覆盖未核对的新增提交。
先上传 main/V2.0.0 并核对远端指向，再删除旧版本标签；不创建包含旧敏感历史的备份引用。
本地旧标签、工具快照引用、reflog 和无引用历史对象在发布完成后清理。
Benchmark 中的测试基线 ID 是测量时的历史记录，不是保留旧提交的 Git 引用。

该操作清理仓库当前可达历史；已存在的外部 clone、GitHub 缓存或按旧对象 ID 访问的保留内容，
不能仅凭 Git push 保证从所有副本消失。若需要服务端彻底清除旧缓存，应联系托管方处理。

详细扫描数目及门禁结果见 privacy_scan.json。审查记录不复述被移除的真实路径或私人邮箱。
